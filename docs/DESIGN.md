# 冒险工匠（Adventure Crafter）桌面辅助软件设计方案

> 《The Adventure Crafter》（Tana Pigeon 著，Word Mill Games 出版）辅助软件。
> 本文档为已确认的实施设计方案。

## 最终决策（已确认）

| # | 决策 | 说明 |
|---|------|------|
| 1 | F13 不实现 | 「编辑规则快捷操作」（「忽略此结束」当「无」、「将下一转折点指定为结束」）不实现，相关操作**交由玩家自行操作** |
| 2 | 建立公开 GitHub 仓库 | 仓库名 `adventure_crafter` |
| 3 | 命名规范 | 项目代号 `adventure_crafter`（仓库/目录/包名/代码标识符）；应用名 **Adventure Crafter** 仅用于 UI 界面显示与文档标题 |

核心原则：

1. 数字化优先，纸笔妥协机制直接简化（如：条目删除即移除，无划掉/列表满规则；「无」不强制重掷）。
2. 软件只查询/展示掷骰结果，不替玩家做决定；列表数据只能由玩家手动修改，软件仅提示。
3. 本版本不做 Mythic GME 结合（列入未来扩展）。

已确认的设计细目：

- 情节点掷骰 = 1d100 + 1d10 主题骰（非 2d10）。
- 主题交替计数器自动追踪并在界面显性展示（A）。
- 条目权重计数器（1~3）由玩家手动增长（B）；全局设置「允许权重超过 3」默认关闭（B-附加，仿 GME `allowUnlimitedListCount`）。
- 列表分页：每页 25 行，行 n 覆盖 4n−3~4n；多页时先掷 1d页数 再掷 1d100；空行显示默认提示（C）。
- 元情节点/特殊特质 93-100 的副作用只显示原文，不自动执行。
- 角色铸造「掷两个」结果只提示，不自动处理。
- 情节点表 = 查询弹窗。

## 二、架构设计

### 2.1 模块划分

```
lib/
├── main.dart                  # 服务注册与启动加载
├── helpers/                   # rollDie/roll100/roll10、rowForRoll、纯逻辑引擎
├── data/                      # 静态规则表加载 + 冒险数据模型
├── services/                  # 规则表 / 冒险 / 全局设置 / 掷骰日志服务
├── storage/                   # 本地存档（.io 文件系统 / .web 条件导入）
└── ui/
    ├── adventure_index/       # 冒险列表页
    ├── adventure/             # 冒险主界面（导航栏聚合各页）
    ├── themes/                # 主题装配 + 交替计数器展示
    ├── characters/            # 情节线/角色分页列表（共用组件）
    ├── cast_character/        # 角色铸造向导
    ├── turning_points/        # 转折点编辑 + 情节点掷骰
    ├── tables/                # 静态表查询弹窗（情节点/元/三表）
    ├── roll_log/              # 掷骰记录
    ├── global_settings/       # 权重上限开关、数据表浏览
    └── widgets/               # 复用小组件
```

### 2.2 数据结构

**A. 静态规则表**（`assets/rules/*.json`，随应用打包，只读；由 `tools/generate_rules.py` 从中文译本生成并校验）

- `plot_points.json`：情节点行 × 5 主题掷骰区间矩阵（null=该主题无此结果；区间互斥且并集覆盖 1-100）
- `meta_plot_points.json`：7 条 {id,title,desc,min,max}
- `character_traits.json` / `character_identities.json` / `character_descriptors.json`：区间表（含 rollTwo 标记与原文说明）
- `random_themes.json`：1-10 主题区间
- `theme_priorities.json`：主题骰 1-4→第1优先 / 5-7→第2 / 8-9→第3 / 10→交替指针
- `list_defaults.json`：两列表各 25 行默认提示

**B. 冒险存档**（JSON 文件，每冒险一个；`schemaVersion` 校验）

```jsonc
{
  "schemaVersion": 1,
  "id": "...", "title": "...", "date": "...", "notes": "",
  "themes": ["tension", "personal", "social", "mystery", "action"],
  "alternator": 4,
  "plotlines":   { "entries": [...], "pages": [[entryId|null, ...25 行], ...] },
  "characters":  { "entries": [...], "pages": [...] },
  "turningPoints": [ { "index": 1, "plotlineId": 1, "status": "development",
                       "slots": [ { "themeId": "...", "plotPointId": "...",
                                    "metaId": null, "invoked": [2], "notes": "" } x5 ],
                       "notes": "" } ]
}
```

要点：

- **权重 = 网格中引用该条目的行数**；「+1」= 把下一个空行（按页序扫描，页满自动扩展）分配给该条目，玩家显式点击触发
- 行槽 `null` → 界面显示该行的静态默认提示
- 交替计数器只存 `4|5` 一个值，主题骰掷出 10 时使用当前指针并翻转写盘

### 2.3 核心流程

**转折点生成（主流程）**

```
新转折点
  ├─ 情节线列表掷骰：[多页? 1d页数] + 1d100 → 行
  │     ├─ 行有条目 → 聚焦该情节线（提示可手动 +1 权重）
  │     └─ 空行 → 默认提示（新情节线/选择最合理的情节线，可手动指定）
  ├─ 循环掷情节点槽位 1→5：
  │     主题骰 1d10 → 1-4第1优先 / 5-7第2 / 8-9第3 / 10→交替指针(用后翻转)
  │     情节点骰 1d100 + 主题 → 查情节点表
  │        ├─ 普通结果 → 填入槽位（可编辑）
  │        ├─ 「无」 → 槽位记「无」（不强制重掷）
  │        └─ 96-100 → 弹元情节点表掷 1d100 → 显示结果+原文（副作用不执行）
  │     （「我不知道」：重掷 / 改无 / 改最合理）
  └─ 玩家解读，手动设置转折点状态（发展/结束）与情节线列表变更
```

**角色铸造（向导）**：掷特殊特质 1d100（93-100 只显示原文说明）→ 掷身份 1d100（1-33 提示掷两个）→ 掷描述词 1d100（1-21 提示掷两个）→ 命名 → 手动加入角色列表。

**列表掷骰（情节线/角色通用）**：[页数>1? → 1d页数] → 选中页；1d100 → 行号 = ⌈d100/4⌉；行有条目 → 征引（仅提示），空行 → 默认提示。

## 三、技术选型

| 选型 | 理由 |
|---|---|
| Flutter 3.38.10 | 单代码库出 Windows/Android/Web 三端；构建链已趟平 |
| GetX | 与参考项目（mythic-gme-adventures）一致，SavableMixin/服务注册/响应式同构 |
| assets JSON 静态表 | 规则表只读、体量小，无需数据库 |
| 手写 toJson/fromJson + schemaVersion | 存档结构简单；版本校验保证未来可迁移 |
| 纯本地存储（.io/.web 条件导入） | 无云同步；zip 导入导出列入 M3 |
| 不用 flutter_quill | 笔记为短文本，普通输入框即可 |
